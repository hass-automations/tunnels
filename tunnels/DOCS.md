# Tunnels — документация аддона

## Для чего этот аддон

**Tunnels** — это аддон Home Assistant, который запускает **VPN-клиент** (сейчас поддерживается **WireGuard**) прямо на хосте Home Assistant. Он нужен для **безопасного удалённого доступа** к умному дому извне локальной сети.

### Типичный сценарий

| Где вы | Как подключаетесь |
|--------|-------------------|
| **Дома** | Обычная локальная сеть (Wi‑Fi). Home Assistant доступен по внутреннему адресу (например `http://192.168.1.x:8123`). VPN не нужен. |
| **Вне дома** | Включаете VPN (например WireGuard на телефоне или ноутбуке) и заходите в Home Assistant по VPN-адресу (например `http://10.0.0.2:8123`). Аддон поднимает WireGuard-интерфейс на хосте HA, поэтому хост виден внутри VPN. |

То есть: аддон не открывает Home Assistant в интернет напрямую. Доступ идёт через ваш VPN (например через VPS с WireGuard-сервером), что безопаснее, чем проброс портов или облачные туннели.

### Что умеет аддон

- **Запуск и остановка** WireGuard-туннеля (кнопки Start / Stop в веб-интерфейсе).
- **Редактирование и сохранение** конфига WireGuard в UI (конфиг сохраняется в папку аддона и переживает перезапуск).
- **Диагностика**: статус интерфейса, IP, вывод `wg show`, лог последних действий.
- **Автозапуск** (опционально): поднимать VPN при старте аддона.

Интерфейс доступен **только через Ingress** Home Assistant (встроенная панель аддона), без прямого доступа по порту из LAN.

## Установка и первый запуск

1. Установите аддон (из репозитория или HACS, в зависимости от способа распространения).
2. В **Настройки → Дополнения → Tunnels** откройте вкладку **Конфигурация** и при необходимости измените параметры (см. ниже).
3. Создайте конфиг WireGuard (клиентский) и положите его в папку конфигурации аддона под именем из опции `config_file` (по умолчанию `wg0.conf`).  
   Точный путь к папке: **Информация** аддона → «Add-on config folder» (часто что-то вроде `/addon_configs/<uuid>/`).
4. Сохраните конфигурацию аддона и запустите аддон.
5. Откройте панель аддона (**Tunnels** в боковом меню или из карточки аддона). В интерфейсе можно проверить статус, отредактировать конфиг, нажать **Start** для поднятия туннеля.

## Конфигурация аддона

Параметры задаются во вкладке **Конфигурация** аддона.

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `interface` | строка | `wg0` | Имя интерфейса WireGuard. |
| `config_file` | строка | `wg0.conf` | Имя файла конфига в папке конфигурации аддона. Файл должен лежать в «Add-on config folder». |
| `autostart` | bool | `false` | При `true` при старте аддона автоматически поднимать VPN (с задержкой `autostart_delay_seconds`). |
| `autostart_delay_seconds` | число | `5` | Задержка в секундах перед автоподъёмом VPN (например 3, 5, 10, 15, 30, 60, 120, 300). |
| `ingress_allow_ip` | строка | `172.30.32.2` | IP, с которого разрешён доступ к приложению (Ingress). Обычно не меняют. |
| `log_level` | список | `info` | Уровень логов: `debug`, `info`, `warning`, `error`. |

### Где лежит конфиг WireGuard

- **На хосте:** в папке конфигурации аддона, имя файла — значение `config_file` (например `wg0.conf`). Путь смотрите в **Информация** аддона.
- **В контейнере:** при старте аддона файл копируется в `/etc/wireguard/<interface>.conf`. Редактирование и сохранение в UI пишет конфиг в постоянное место и при необходимости перезапускает интерфейс.

## Пример конфига WireGuard (клиент)

Файл в папке аддона, например `wg0.conf`:

```ini
[Interface]
PrivateKey = <ваш_приватный_ключ_клиента>
Address = 10.0.0.2/32

[Peer]
PublicKey = <публичный_ключ_сервера>
Endpoint = <IP_VPS>:51820
AllowedIPs = 10.0.0.0/24
PersistentKeepalive = 25
```

Подставьте свои ключи и IP. Подсеть VPN не должна пересекаться с вашей домашней LAN. Полная настройка сервера WireGuard (на VPS) и генерация ключей описаны в файле **article.md** в этом репозитории.

## Веб-интерфейс (панель аддона)

Открывается через Ingress (кнопка «Открыть» у аддона или пункт **Tunnels** в меню).

- **Статус:** UP / DOWN, время последнего обновления, бейдж «supported» для WireGuard.
- **Configuration:** текстовое поле с конфигом WireGuard. Кнопки **Save**, **Validate**, **Copy**. После сохранения, если туннель был поднят, он перезапускается с новым конфигом.
- **Controls:** **Start** — поднять туннель, **Stop** — опустить, **Refresh** — обновить статус, **Status JSON** — открыть JSON статуса в новой вкладке.
- **Сводка:** протокол, IP интерфейса, имя интерфейса, путь к конфигу.
- **Last actions:** локальный лог последних операций (start/stop/save).
- **Diagnostics:** вывод диагностики (Primary) и сырой JSON (Raw), кнопка копирования.

Обновление статуса выполняется автоматически раз в несколько секунд и по кнопке **Refresh**.

## Безопасность

- Панель аддона рассчитана на использование **только через Ingress**. Прямой доступ по порту (например 8099) с других IP блокируется (403).
- Аддон работает с `host_network: true` и правами `NET_ADMIN`, чтобы управлять интерфейсом WireGuard на хосте. Не давайте доступ к панели недоверенным лицам.

---

## Поддерживаемые протоколы

- **WireGuard** — полностью поддерживается: start/stop, редактирование конфига, диагностика.
- **OpenVPN** — в UI есть заглушка (пункт в выборе протокола), бэкенд пока не реализован.

## Устранение неполадок

1. **Конфиг не найден**  
   Убедитесь, что файл с именем из `config_file` лежит в папке конфигурации аддона (см. **Информация** аддона).

2. **Start не поднимает туннель**  
   Проверьте логи аддона. Убедитесь, что в конфиге есть секция `[Interface]` и `PrivateKey`, что `Endpoint` и ключи корректны и сервер WireGuard на VPS запущен и доступен (порт 51820/udp).

3. **После смены конфига на диске**  
   Перезапустите аддон, чтобы скопировать обновлённый файл в `/etc/wireguard/`. Либо отредактируйте конфиг в UI и нажмите **Save**.

4. **Диагностика**  
   В панели аддона в блоке **Diagnostics** смотрите вывод `wg show` и **Last actions** — там видно результат последних start/stop/save.
